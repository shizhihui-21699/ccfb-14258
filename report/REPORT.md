# 设备绑定安全存储：基于 SRAM PUF 的门禁控制板凭据加密

**问题**：门禁控制板容易被整块拆下、把闪存芯片数据原样拷到另一块板子，复制出一台能开门的设备。

**目标**：用每块芯片制造时形成的独特物理差异（PUF）生成只属于这块芯片的密钥，把凭据加密绑定在上面；**闪存数据拷到别的芯片上就解不开**。

**难点**（本题明确要求处理）：
1. PUF 每次读都有少量位翻转，温度和电压变化会放大误差；
2. 芯片老化后特征漂移；
3. 纠错辅助数据（helper data）存在闪存里，攻击者能拿到并反复篡改来套取信息。

---

## 1. 结论摘要

| 项目 | 结果 |
|---|---|
| 克隆防护 | 同一份闪存镜像拷到 50 块不同芯片上，**0/50 能解出凭据** |
| 温度鲁棒性 | −40 °C ~ +125 °C 全温度范围 **100% 解锁**（默认 t=32 设计） |
| 电压鲁棒性 | 2.6 V ~ 3.8 V **100% 解锁** |
| 老化鲁棒性 | 20 年老化 **100% 解锁**；老化+高温交叉测试 100% |
| 门禁规范包线 | −20~70 °C、2.9~3.5 V、10 年：t=20 设计 **13500/13500 全部成功**，密钥 690 bit |
| 辅助数据篡改 | 500 次单比特篡改 **0 次误接受**；棘轮模式 16 次即锁定 |
| 离线暴力破解 | 密钥空间 2^282（默认），远高于 128-bit 安全目标 |
| 朴素方案对照 | 不做稳定性选择的朴素设计在 85 °C 仅 **0~15%** 成功率 → 本方案的核心价值所在 |

> **重要声明**：本仓库的 PUF 物理、噪声、温度/电压/老化模型均为**仿真**（`src/puf.h`），没有在真实硅片上测量。所有成功率是在该仿真模型下的结果，用来验证算法与架构的正确性和鲁棒性趋势，不能替代真实芯片的认证测试。报告第 7 节列出了模型的假设与局限。

## 2. 方案总体架构

```
                        工厂注册（可信环境）                        现场解锁
 ┌──────────────────────────────────────────┐   ┌───────────────────────────────────────┐
 │ 1. 多温度/多电压读 PUF 阵列                │   │ 1. 当前温度/电压下读 PUF 阵列（多次平均）│
 │ 2. 标记"易变单元" → 稳定单元子集           │   │ 2. 用 helper 中记录的稳定单元索引取值     │
 │ 3. 稳定单元按块做 BCH 编码                 │   │ 3. BCH 纠错译码（带可选软擦除）          │
 │ 4. 码字 ⊕ 参考位 = helper（一次性掩码）    │   │ 4. 恢复 K_raw → HKDF → 密钥              │
 │ 5. K_raw（TRNG）→ HKDF → 32B 密钥         │   │ 5. HMAC 128-bit tag 校验（唯一接受标准）  │
 │ 6. 用该密钥 AEAD 加密凭据 → 存入闪存       │   │ 6. AEAD 解密凭据（绑定 device_id）        │
 └──────────────────────────────────────────┘   └───────────────────────────────────────┘
        闪存内容：helper + 加密凭据 + 明文元数据 + 失败计数器
```

**关键设计点**：
- 密钥 **不是直接等于 PUF 位**，而是 `HKDF(K_raw, digest(helper))`，其中 `K_raw` 是注册时 TRNG 生成的**均匀随机数**。这消除了 PUF 位偏置（bias）对密钥熵的影响，也保证即使 helper 泄露，攻击者也拿不到 PUF 的原始响应。
- **128-bit tag 是唯一的接受判据**。BCH 译码器无论返回什么，都必须通过 tag 校验；这使多候选搜索、擦除策略都安全——错误候选被 2^-128 概率拒绝。
- 凭据用 AEAD 加密，AAD 绑定 `device_id + scheme + salt + slot`，篡改任何字段都会解密失败。

## 3. 核心创新：稳定单元子集选择

### 3.1 问题诊断

我先实现了"朴素"方案（直接把 PUF 位送进 BCH 纠错），并测量了每个 255 位块在高温下的错误数（8 块、复现命令见下方）：

| 条件 | 每块错误数 min/med/max | t=32 能否纠 |
|---|---|---|
| 25 °C | 0 / 1 / 4 | 能 |
| 85 °C | 17 / 25 / 28 | 勉强（临界） |
| 105 °C | 19 / 33 / 37 | **不能** |
| 125 °C | 26 / 39 / 48 | **不能** |

> 复现：`tests/` 中的 `decode` 测试 + `tools/experiments baseline` 的 naive 行；错误数探针可由 `FeParams::select_stable=false` 配合 `decodable_blocks` 得到。

**根本原因**：PUF 的误差**不是随机噪声**，而是**系统性漂移**——少数"弱单元"（制造失配小、温度/电压系数大）会在板子升温/降压时**成片翻转**，且每次都是同一批单元。诊断显示：在 −20~100 °C、2.7~3.6 V 标定网格上测过之后，标定识别出的易变单元约占阵列 **22%**，而它们覆盖了后续运行期错误的 **99~100%**（65~105 °C）；只有 125 °C 这种远超门禁范围的极端温度下覆盖率降到 ~83%。

### 3.2 解决方案

**在工厂注册时做多温度/多电压标定，把"会翻转的单元"整体剔除，只用"观测到稳定"的单元构造码字。**

- 稳定单元（~78%）的误差率极低，纠错预算几乎不必花在温度上；
- 代价是可用单元减少（2048 → ~1530 个），密钥容量下降，但换来的是温度/电压/老化的巨大裕度。

这个设计把"物理上可预测的漂移"和"物理上不可预测的噪声"分开处理：前者靠**标定时剔除**，后者靠**BCH 纠错**。

### 3.3 效果对比（直接证据）

同一条实验、同样的芯片与条件，朴素方案 vs 稳定子集方案：

| 设计 | t | 密钥(bits) | 85°C | 老化10年@25°C | 老化20年@25°C | 老化10年+85°C |
|---|---:|---:|---:|---:|---:|---:|
| 朴素（全单元） | 20 | 920 | **0.0%** | 2.5% | 0.0% | 0.0% |
| 稳定子集 | 20 | 690 | 80.0% | 97.5% | 100.0% | 75.0% |
| 朴素（全单元） | 32 | 376 | **15.0%** | 62.5% | 47.5% | 0.0% |
| **稳定子集（默认）** | **32** | **282** | **100%** | **100%** | **100%** | **100%** |

> 朴素方案在 85 °C 只有 0~15% 成功率，稳定子集方案 100%。这就是本设计的全部价值：**同样的物理、同样的码，换个"选哪些位"的策略，从不可用变成可用。**

## 4. 实验结果

以下所有表格由 `tools/make_report.py` 从 `results/experiments.log`（C++ 实验程序原始输出）机械生成，数字与程序输出一致。完整表格见 `report/tables.md`。

### 4.1 温度与电压

默认设计 t=32（BCH(255,47,32)，6 块，282-bit 密钥）：

- **温度**：−40 / −20 / 0 / 25 / 45 / 65 / 85 / 105 / 125 °C → **全部 100%**
- **电压**：2.6 / 2.8 / 3.0 / 3.3 / 3.6 / 3.8 V → **全部 100%**
- **热+低压交叉**（65/85/105 °C × 2.8/3.0 V）→ **全部 100%**

### 4.2 老化

- 老化 0~20 年（25 °C）：**全部 100%**
- 老化 × 温度网格（0/5/10/15 年 × −20/25/70/85/105 °C）：**全部 100%**

极端边界实验（单独探针，见 `results/experiments.log` 的 bounds 段）显示稳定单元子集方案在 **−80 °C ~ +175 °C、45 年老化**内仍 100%，失效点在 ~200 °C 或 ~40 年（t=32）。

### 4.3 设计空间权衡（t 的选择）

t 越大纠错越强、抗老化/温度越好，但每块信息位越少、密钥越短：

| t | k | 密钥(bits) | 最大温度 | 最大老化 |
|---:|---:|---:|---:|---:|
| 12 | 163 | 978 | 130 °C | 15 年 |
| 16 | 131 | 786 | 130 °C | 15 年 |
| 20 | 115 | 690 | 145 °C | 25 年 |
| 24 | 91 | 546 | 145 °C | 30 年 |
| 28 | 71 | 426 | 160 °C | 35 年 |
| **32** | **47** | **282** | **175 °C** | **45 年** |
| 40 | 47 | 282 | 175 °C | 55 年 |

**门禁控制板规范包线实测**（−20~70 °C、2.9~3.5 V、0~10 年，30 颗芯片 × 全网格 × 10 次）：

| t | 密钥(bits) | 成功率 | 样本数 |
|---:|---:|---:|---:|
| 20 | 690 | **100.000%** | 13500 |
| 24 | 546 | 100.000% | 13500 |
| 28 | 426 | 100.000% | 13500 |
| 32 | 282 | 100.000% | 13500 |

**工程建议**：纯门禁应用（室内、−20~70 °C、10 年）用 **t=20** 即可提供 690-bit 密钥且 100% 可靠；若门禁板要装在户外、无温控、寿命更长，选 **t=32** 换取 175 °C / 45 年裕度。代码两行参数即可切换。

## 5. 攻击分析

| 攻击 | 方法 | 结果 |
|---|---|---|
| **闪存克隆** | 复制整个闪存镜像到 50 块不同芯片 | **0/50 解出凭据**（PUF 密钥不同 → AEAD 失败） |
| **辅助数据篡改** | 单比特翻转 helper payload，500 次 | **0 次误接受**（tag 拒绝 + 稳定单元索引错位） |
| **辅助数据预言机** | 反复篡改、观察是否泄露信息 | 棘轮模式下 **16 次即锁定**，每次尝试成本递增 |
| **密文篡改** | 翻转凭据密文 1 bit | 检测到（AEAD tag 失败） |
| **离线暴力破解** | 拿到 helper+tag，无 PUF | 需 2^282 次（K_raw 熵），≥ 2^128 安全目标 |

### 5.1 为什么辅助数据篡改套不出信息

这是本题的关键威胁。设计上有三层防护：

1. **tag 是唯一接受标准**：篡改 helper 后，BCH 可能译出某个码字，但导出的密钥几乎必然过不了 128-bit tag 校验。攻击者从"成功/失败"这一比特得到的信息是 2^-128 量级，无实际价值。
2. **失败模式不泄露**：`UnlockMode::Constant` 模式下所有失败返回同一个错误，不区分"PUF 失败"和"凭据失败"；`Ratchet` 模式额外加重试惩罚。
3. **失败计数持久化**：`fail_count` 存在闪存，攻击者若擦除它需要物理改写（且可配合单调计数器/OTP 熔丝防回滚）。棘轮模式默认 16 次后锁死。

**残留风险（如实说明）**：若攻击者能无限次物理重置失败计数器（例如重新烧写整片闪存），则预言机攻击理论上可无限进行；但每次尝试仍是 2^-128 的盲猜，统计上不可行。真实产品应把失败计数放在 OTP/单调计数器里，本仿真用普通计数器近似。

### 5.2 为什么克隆无效

克隆者拿到的闪存里有：helper（码字 ⊕ **原芯片**参考位）、加密凭据。在另一块芯片上，PUF 响应不同（芯片间理想汉明距离实测均值 ~50.05%，190 对，接近理想的 50%），BCH 译出的 `K_raw'` 是错的 → HKDF 密钥错 → AEAD 解不开。**凭据的明文从未离开加密保护**。

## 6. 实现结构

```
src/
  common.h          RNG、位运算、hex 等基础工具
  crypto.h          SHA-256 / HMAC / HKDF / ChaCha20 / AEAD（全部自测 RFC 向量）
  gf256.h           GF(2^8) 有限域
  bch.h             二进制 BCH(255,k,t) 编解码，支持错误+擦除联合译码
  rs.h              Reed-Solomon(255,k)（备用/对照，同样支持错误+擦除）
  puf.h             SRAM PUF 仿真（失配、温度、电压、老化、RTS 噪声、硬失效）
  fuzzy_extractor.h 码偏移模糊提取器 + 稳定单元子集选择
  device.h          设备绑定凭据存储、解锁策略、攻击面
tools/
  demo.cpp          端到端演示（注册→解锁→克隆→篡改）
  experiments.cpp   全部实验（温度/电压/老化/攻击/设计扫描/包线）
  make_report.py    从实验 CSV 生成报告表格
tests/
  test_crypto.cpp   密码学原语（RFC 4231 / 5869 / 8439 / FIPS 180-4 向量）
  test_bch.cpp      BCH/RS 纠错（错误、擦除、联合、超限）
  test_fuzzy.cpp    模糊提取器与设备层（跨芯片、温度、老化、篡改、锁定）
```

**构建与运行**：

```bash
cmake -S . -B build -DCMAKE_BUILD_TYPE=Release
cmake --build build -j
ctest --test-dir build --output-on-failure     # 3 个测试可执行文件全部通过
./build/demo                                    # 端到端演示
./build/experiments all > results/experiments.log
python3 -I tools/make_report.py                 # 生成 report/tables.md
```

## 7. 仿真模型的假设与局限（务必阅读）

1. **所有 PUF 物理都是仿真**。`src/puf.h` 建模了：制造失配（N(0,1)）、每单元温度/电压灵敏度、阵列级共模偏置、随温度/电压/老化的读噪声、稀疏 RTS 尖峰、老化的失配收缩/随机游走漂移/永久翻转。参数经过标定使同条件单次读翻转率 ~0.8%、芯片间距离 ~50%（实测均值 50.05%），与文献中 SRAM PUF 的量级一致，但**不等于任何具体工艺**。
2. **稳定单元选择依赖工厂标定**。本方案假设注册时能在受控条件下遍历温度/电压网格（这本来就是芯片出厂测试的一部分，成本可控）。若无法标定，只能用保守的 t 或本文 3.1 节的朴素方案——后者在高温下基本不可用。
3. **"稳定"是相对的**。标定只覆盖给定网格。若实际工作条件远超标定范围（如 −80 °C 或 175 °C），稳定单元也会开始翻错；仿真显示 t=32 设计在 ~200 °C 才失效，但这不代表真实芯片。
4. **老化模型是现象学的**。真实 NBTI/HCI 退化和温度/偏置历史强相关，本模型用随时间单调的经验漂移近似，不能预测特定工艺的寿命。
5. **固定密钥 `K_raw` 由 TRNG 提供**。安全前提是注册环境的 TRNG 可信、且 `K_raw` 在注册后立即清零（代码中已 `secure_wipe`）。
6. **失败计数器**用普通闪存字近似，未模拟 OTP/单调计数器的防回滚；真实部署应使用硬件防回滚。
7. **侧信道**：本仿真未建模功耗/电磁侧信道、故障注入（电压毛刺、激光）。真实产品需额外防护。
